Unified Design Logic Architecture

StatusIssued for workshop
RevisionH
Date2026-11-16

Problem

  • Calculations are spread across servers and project folders in many formats and languages. Their origin, author, code edition and quality are often unknown.
  • The same checks are rebuilt on every project. The versions are not connected, so a correction made in one is not carried to the others and the same errors are repeated.
  • Many calculations are incomplete: assumptions, limits of validity and references to the design code are missing.
  • Spreadsheets and calculation sheets are easy to create and read but hard to version and reuse; code is reusable but not user-friendly, and does not read as a calculation.

Solution

A knowledge base that holds one verified design logic for each topic of structural engineering. From this single logic we can create customisable calculation reports, engineering tools such as spreadsheets and calculation sheets, and AI-assisted tools, all giving the same results.

The knowledge base is built by a pipeline that retrieves the calculations we own, distils the design logic in them, compares it with the design codes and consolidates it under engineer review. It is version-controlled, shows which topics are covered and where the gaps are, and improves with every project that uses it.

Proposed architecture

The knowledge base is built and maintained by a pipeline of eight modular components, grouped in four phases: ingestion, distillation, knowledge base, and use and maintenance. Each component is built and validated separately and has its own challenges to resolve. Engineers review the logic at two points: before consolidated logic enters the knowledge base, and before a correction is released. Select a component for its description.

Components

Ingestion · 1

Retrieval and curation

Retrieves calculations and reports from existing project databases and curates the files that enter the pipeline.

  • Searches project databases, servers and document management systems; files can also be selected by hand
  • Records the metadata of each file where available: project, department, author, date, design code and design topics
  • Removes duplicates and superseded versions; retains files that are relevant, complete, of known origin and to a current code edition
  • New calculations enter through the same route
Ingestion · 2

Conversion

Parses each document into a machine-readable format from which the original values can be recreated.

  • Readers for Excel, Mathcad, Word, PDF, Python and Jupyter; scanned documents are read by text recognition
  • Each converted file is recalculated and compared with the values in the original before it is accepted
  • Each reader is validated separately
Distillation · 3

Decomposition

Distils the design logic from each file and maps it across the topics of structural engineering.

  • Design logic is separated from project data
  • The topic map is prepared in advance by AI and pre-populated with the design logic of the codes
  • AI assists in extracting the logic: elements, expressions, parameters, warnings, pitfalls and design background
  • A coverage map shows what is covered, what is missing and where sources are many
Distillation · 4

Consolidation

Merges the logic from many sources into one unified design logic through consensus mechanisms.

  • Consensus rules, deterministic or probabilistic, use sampling, benchmarking and testing across sources to classify them as agreeing or disagreeing
  • Each object is evaluated over a common, sampled parameter domain. Sources whose results converge within a specified tolerance are merged, so one logic is reviewed instead of many. Where results do not converge, the cause is identified, such as a simplification, a unit or a misread value, or the difference is referred to an engineer
  • Agreement between sources is not proof of correctness. Accuracy is established by benchmarks against independent references: code worked examples, design guides, hand calculations and FE results
  • Each new calculation is classified as already covered, an extension of an existing topic, or a new design topic
  • Engineers review the resulting specifications and sign off those that enter the knowledge base. This is the first point of human review
Knowledge base · 5

Object generation

Turns each unified design logic into a modular, tested calculation object.

  • The object specification is software-agnostic: Python code, Excel spreadsheets and Mathcad worksheets are generated from the same logic
  • Objects are benchmarked against the original files, other checked projects and independent references
Knowledge base · 6

Repository and search

A secure, version-controlled knowledge base with an AI-curated search engine.

  • Finds the relevant calculation object for a design task
  • Checks every new calculation: already covered, an extension, or a new design topic
  • Versions, access rights, approvals and written rules for contributors and for the AI
  • An API makes the objects available to other workflows and tools
Use and maintenance · 7

Extraction

Produces multi-format calculations, reports and tools from a single source of truth.

  • Self-documenting calculations: equation, substituted values, result and clause for each step, at the quality of our existing calculations
  • Customisable reports over many design cases, in the company template, as PDF or Word
  • Engineering tools: spreadsheets and Mathcad worksheets with live formulas
  • AI-assisted tools that use the same calculation objects
  • Every deliverable carries the version of the logic it was made from and is signed off by the project engineer and checker, as today
Use and maintenance · 8

Maintenance

Audits the knowledge base through scheduled health checks and provides a route for corrections and new components.

  • Health checks re-run every benchmark whenever a change is made
  • Corrections and new components pass consolidation and testing again and are released as a new version
  • Engineers review calculations in use and approve every correction and new component
  • AI can propose fixes directly from user feedback
